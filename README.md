# 今日の仕事整理ツール（制作 #001）

Instagram公開作品として制作した、業務効率化のための小さなWebアプリです。

## 制作した理由

仕事や副業をしていると、「今日やることが色々あるはずなのに、頭の中がごちゃごちゃして何から手をつければいいか分からない」という瞬間があります。
その状態を、紙に書き出すような感覚でパッと整理できたら少しラクになるのではないか、という思いから制作しました。

コンセプトは、

> 今日の仕事を、少し整理。
> 手作業を、少しラクに。

大きな機能を詰め込むのではなく、「小さいけれど、本当に使える」ことを優先しています。

## 解決したいこと

- 頭の中のタスクが多すぎて、優先順位を考える前に疲れてしまう
- 「今すぐやるべきこと」と「後回しにしていいこと」が混ざったままになっている
- タスク管理ツールを新しく覚えるほどではない、ちょっとした整理がしたい

## 主な機能

- タスクをまとめて入力できる大きな入力欄（改行・読点・カンマ区切りに対応）
- 「整理する」ボタンで、入力内容を自動的に3つのカテゴリへ分類
  - **今日やる**（最大3件）
  - **5分でできそう**
  - **後回しでもOK**
- 各タスクにチェックを付けられ、完了すると取り消し線＋薄い表示になる
- 「今日の内容をリセット」（誤操作を防ぐため、確認してから削除）
- 「サンプルを試す」で、すぐに動作を確認できる
- 入力内容・整理結果・チェック状態をブラウザ内に保存し、再訪問時も復元

## 振り分け（判定）の仕組み

外部のAIサービスやAPIキーは一切使用せず、**すべてブラウザ内のシンプルなルール判定**で振り分けています。

1. 入力文を、改行・読点（、）・カンマ・「・」で1タスクずつに分割します。
2. それぞれのタスクについて、次の2つの観点を、キーワードと文字数を組み合わせて数値化します。
   - **緊急度**：「至急」「今日」「締切」「明日」「会議」などの言葉があるほど高くなり、「来週」「いつか」「余裕があれば」などの言葉があるほど低くなります。
   - **重さ（時間のかかりそうさ）**：「資料」「作成」「まとめる」「調べる」などの言葉が含まれる、または文章が長いほど「重い」と判定されます。逆に「少し」「簡単」「確認だけ」などの言葉が含まれる、または文章が短いほど「軽い」と判定されます。
   - 例：「メールを1件返信する」→ 短く軽い言葉が多い → **5分でできそう**
   - 例：「明日の会議資料を確認して修正する」→ 緊急度・重さともに高い → **今日やる**
   - 例：「来週の予定を確認する」→ 後回しを示す言葉がある → **後回しでもOK**
3. 緊急度・重さのどちらにもはっきり当てはまらないタスクは、いったん保留にします。
4. 「今日やる」の枠（最大3件）が余っている場合は、保留タスクの中から優先度が高そうなものを優先して割り当てます。安易に「後回しでもOK」に流さないための工夫です。
5. それでも枠に入らなかった保留タスクは、軽さの判定に応じて「5分でできそう」または「後回しでもOK」に振り分けます。
6. 「今日やる」が3件を超えた場合は、優先度の低いものから他のカテゴリに移します。

完璧な精度を目指すものではなく、「だいたい合っている」を目指したシンプルなロジックです。

## 使用技術

- HTML / CSS / JavaScript のみ（フレームワーク不使用）
- `index.html` 1ファイルにHTML・CSS・JavaScriptをすべて記述し、外部ファイルへの依存をなくすことで、どの環境でも確実に同じ見た目・動作になるようにしています
- データの保存には、ブラウザ標準の `localStorage` を使用

## データの取り扱いについて

- 入力したタスク・整理結果・チェック状態は、**お使いのブラウザ内（localStorage）にのみ保存**されます。
- サーバーへの送信や、外部API・外部AIサービスとの通信は一切行っていません。
- 個人情報・実在する業務データ・収益や目標数値などは、本ツールおよびサンプルデータに一切含まれていません。

## デザインについて

- 白ベース＋ネイビー＋淡いブルーを基調にした、清潔感のあるシンプルなデザイン
- 派手なグラデーションは使用せず、業務システムのような硬い印象になりすぎないよう配慮
- 「今日やる」を最も重要なカテゴリとして、見出しをやや大きく・太くして視覚的に目立たせている
- 3カテゴリを淡い色（ブルー／グリーン／グレー）で区別しつつ、全体は落ち着いたトーンを維持

## スマートフォン優先の設計

- スマートフォン（iPhoneの390px前後の画面幅）を基準に設計し、横スクロールが発生しないことを確認済み
- ボタン・チェックボックスはタップしやすいサイズを確保（チェック行は全体をタップ可能）
- PC・タブレットで見る場合も、スマートフォン向けのレイアウトをそのまま中央に表示する方針とし、画面幅による見え方の違いを最小限にしている

## 公開方法（GitHub Pages / Vercel）

このツールはビルド不要の静的サイトです。`index.html` 1ファイルで完結しているため、以下のいずれかの方法でそのまま公開できます。

### GitHub Pages の場合

1. `index.html`（と `README.md`）をリポジトリにアップロードする
2. リポジトリの Settings → Pages を開く
3. 公開するブランチ（例：`main`）とフォルダ（`/root`）を選択して保存する
4. 発行されたURLにアクセスして動作確認する

### Vercel の場合

1. GitHubリポジトリをVercelにインポートする
2. Framework Preset は「Other（静的サイト）」を選択する（ビルドコマンドは不要）
3. デプロイを実行する
4. 発行されたURLにアクセスして動作確認する

## 今後の改善案

- 現在はキーワードと文字数によるルールベースの分類のため、言い回しによっては分類が直感と少しずれることがあります。将来的には、AIを活用した文脈判定（自然な言い回しの揺れも汲み取れる分類）に発展させることも考えられます。
- カテゴリやキーワードをユーザー自身がカスタマイズできる機能
- 完了したタスクを日ごとに振り返れる簡単な履歴表示
- ダークモードへの対応
